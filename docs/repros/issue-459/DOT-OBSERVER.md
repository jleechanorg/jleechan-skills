## Observation protocol

1. Predeclare a 15-minute observation window for this small task; retain the actual start/end time and stop reason. A run still active at the limit is `timeout_nonterminal`, not proof of a premature stop. Do not interrupt earlier merely to manufacture a failure.
2. Do not add “keep going,” enumerate forgotten requests or repair outputs before recording the first terminal reply. A genuine capability error should be recorded with its exact evidence.
3. Preserve the visible user prompt, assistant replies, actual tool receipts available in the product and returned artifacts. Never request hidden reasoning or system instructions.
4. Independently inspect the artifacts below. Distinguish the executor's claims from what the observer verified. Missing tool logs limit conclusions about whether a claimed verification was actually performed.
5. Report a pass if all requested work completed. If work is omitted or misreported, identify the exact requirement and observable contradiction. Repeat an unchanged task in an independent fresh dot before claiming repeatability or frequency; report failed/passed/time-out/infrastructure counts separately.
