# Lightweight AGY reminders: 1,000-line design

## Outcome and decision
Scheduled reminders on Mac and Linux ask each of three configured Dots to continue its own authorized work and report its next action or genuine blocker. AGY generates a short message; the controller alone submits it. Dots retain task ownership and judgment. This is planning only: no service, source runtime, account, or historical ledger changes are authorized by this document.

The prior reviewed design allowed 2,000 lines and left uncertain-send reconciliation underspecified. Replace that design with this specification for the current request. Do not restore the earliest worker unchanged: AGY exit zero did not establish delivery, and its prompt contained obsolete priorities. The currently installed legacy package is a distinct later revision. Preserve it until an explicitly authorized implementation and coordinated replacement.

## Hard size contract
At most **1,000 physical runtime lines**, including blank/comment lines, Python/shell/JavaScript, prompts, schemas, native service templates, installers, compatibility readers, and coordinator-specific changes to any shared file. Tests and prose-only documentation are excluded and reported separately. Executable instructions hidden in documentation count. No minification, semicolon packing, moving logic into tests/shared packages, or importing the discarded engine.

Existing general-purpose AGY, Python standard library, SSH, and the unchanged canonical Dot browser tool are dependencies, not coordinator LOC. Pin their versions/hashes and report Dot runtime and combined footprint separately. The design baseline's Dot scripts contain 1,135 physical lines; this is a source snapshot, not the deployed transport identity. Any required modifications beyond that frozen dependency baseline count against 1,000. Existing coordinator-specific helpers count in full even if copied unchanged. Do not exempt prepared-send or reconciliation additions merely by putting them in Dot.

Per-file runtime allocation (physical lines, not a promise of fit):

The measured existing native service package uses 212 lines, and the existing coordinator process helper uses 341. Neither fits its new allocation unchanged. Reuse their tested invariants but narrow implementation to trusted POSIX child processes and one render/install path; no general process framework. The process wrapper must kill its process group and all observed descendants by PID plus start identity on timeout, bound output/drain, and refuse delivery when observed children survive. Test nested children and inherited-pipe hangs. This is not OS containment of a malicious daemon that escapes before observation; existing browser services are external dependencies, not killed by this wrapper. No unsupported claim of arbitrary descendant containment. The first implementation checkpoint must demonstrate transport, process, migration and installer primitives fit the full manifest. If not, simplify within scope or report the measured conflict; never silently raise the cap, minify, or remove safety.

## Alternatives
1. Restore the earliest small script: simple, but preserves false-success semantics and stale instructions; reject.
2. Trim the portfolio engine: retains collection, grants, budgets, publication and incidental coupling; reject.
3. **Choose a finite reminder worker with a small transactional ledger.** Reuse the browser tool and bounded process helper; remove the portfolio execution path completely.

## Schedule and ownership
Native launchd/systemd timers wake a finite worker; no sleeping batch, resident daemon, catch-up queue or account rotation. Ordered account slots are Mac :00/:20/:40, Linux :30/:50/:10. These are six intentional host/account events per hour, not replicas; the same account's events are 30 minutes apart. Account names, expected sender/room identities, existing SSH aliases and paths come from private machine configuration.

An event key is the exact tuple `(schedule_version, host_role, account, UTC_due_epoch)`. Start only within 120 seconds of due; Linux authority recomputes the slot and validates the claimed role/account. Reject clock discrepancy greater than 30 seconds and clock rollback within an invocation. Late wakes record skipped, never replay. Mac uses the authority clock for admissibility. A claim closes the account to another event until safely settled, so one slow invocation cannot overlap the other host.

A run has a monotonic 1,200-second ceiling: at most 600 for AGY, 180 for a read/probe or send, remaining time for authority calls and cleanup. The narrow process wrapper owns the tested canonical child lifecycle and reports cleanup failures explicitly. No replacement daemon, token budget allocator, provider fallback, or repair call.

## Minimal flow
`native wake -> authority claim -> AGY message -> durable sending intent -> one Dot send -> terminal receipt -> exit`

The AGY prompt contains only trusted reminder instructions: respect current owners, cancellations and approval gates; continue current authorized work; give next action or genuine blocker. No task census, chat history, stale priority list or tool submission instruction. Use the installed official terminal-result envelope and accept a nonempty string of at most 1,200 characters; controller adds a fixed automated-sender label and unique event marker. Invalid, empty, nonzero or timeout output settles no-send before transport begins. AGY is not given a send task; full permissions are not an isolation guarantee, and the coordinator has no general side-effect detector. AGY is a trusted full-permission dependency; unexpected actions are an accepted residual risk, not a ledger-enforced guarantee. A provider failure never authorizes a substitute sender.

Call the canonical local `dot.sh --account <configured-key> send-once <message-file>` with `DOT_ROTATE_ON_LIMIT=0` and `DOT_ALLOW_REMOTE=0`, clearing inherited remote-routing overrides. Add an opt-in strict reminder mode through an explicit CLI argument; preserve default behavior for unrelated Dot callers, and count all added-side diff lines, including replacements, against the frozen baseline. Do not subtract deletions to hide new code. Never use retrying `send`, clear a peer draft, change a browser profile, or let the model choose the account. Pin Node 22 and exact local transport/config fingerprints. Before starting transport, recheck stop state, fingerprints and claim; wrong session/room identity is no-send. The current baseline tool has fuzzy message matching and may clear a matching stale draft: it does NOT yet establish this stricter contract. Count and test the minimum transport changes needed for exact identity, untouched peer drafts, exact full-message marker/body echo and read-only reconciliation; activation is blocked until that behavior is proven. Do not import the larger prepared portfolio sender to evade this work.

Once a send subprocess can have started, timeout, lost output, nonzero exit or an ambiguous receipt means uncertain, unless the pinned transport supplies a tested explicit before-click no-send result. Delivered requires natural exit zero, one exact standalone receipt, exact new outbound message echo including the event marker and full body, correct sender/room identity, and successful owned-child cleanup. A blank composer or a 95-percent body match is insufficient. Do not classify activity/blockers by keywords.

## Transactional state and recovery
One Linux SQLite file is the sole delivery authority. SQLite standard-library transactions use `BEGIN IMMEDIATE`; database and directory are private, local, durable, with `synchronous=FULL`. Never put the database on a network filesystem. Short authenticated SSH requests carry structured JSON on stdin to the same broker CLI; no shell interpolation of message/config data. Keep transactions short; never hold one across AGY/browser work.

Tables: `events(event_key PRIMARY KEY, account, host_role, due_epoch, deadline_epoch, token, phase, message_digest, original_outcome, receipt_json, reason)`; `holds(account, event_key, PRIMARY KEY(account,event_key))`; `resolutions(event_key PRIMARY KEY, kind, proof_digest, proof_json)`; `imports(source_path, source_sha256, record_key, event_key, PRIMARY KEY(source_path,source_sha256,record_key))`. `kind` is positive_readback or operator_release. `phase` is claimed, sending, terminal. A claim rejects an account while ANY hold for it exists, then atomically inserts event and its account/event hold. Multiple imported historical holds can coexist and must each be resolved; releasing one never unblocks the others. The client generates and durably saves its event/token in the host-local journal defined below before RPC. An identical retry returns the same claim; another token cannot assume it. Tokens correlate one event and never manufacture authority. Status queries are safe; the client never reruns a locally started event after a lost claim reply.

Authority STOP is presence of `STOP` beside the Linux database, inspected by the broker before claim and begin_send. It applies to both hosts; a local Mac STOP is checked by its own worker and is not implicitly replicated. Broker requests contain action, role/account/event/token and action-specific receipt/proof; no arbitrary paths or SQL. Late/duplicate skipped wakes produce a structured local result but insert no hold. The event reason holds the latest deterministic protocol reason; original terminal receipt remains immutable. No model classification is stored.


`begin_send(event, token, message_digest)` commits sending intent before spawning transport. `finish(event, token, outcome, receipt)` stores original receipt and terminal outcome atomically. Delivered or proven no-send releases that event's account hold in the same transaction. Uncertain keeps it. Duplicate finish is idempotent only for identical content; conflicting finish fails without mutation. Crash before or after commit returns either the complete old or complete new state. Never expire a sending/uncertain hold on elapsed time, process death, a new slot or schedule version. A claimed event past its authority deadline may be atomically finalized no-send and released: begin_send accepts ONLY a live claimed event before that same deadline, and the worker cannot spawn transport without a positive begin_send response. Serialize deadline cleanup and begin_send in the same transaction. Thus no-send recovery is backed by the irreversible absence of sending intent, not absence of a chat message. If begin_send committed but its reply was lost, phase is sending and the account remains held.

**Broker-enforced transition matrix:** `finish` validates event/account/token, phase, persisted message digest and the exact typed receipt before mutation. From claimed, only pre-dispatch no-send is allowed; delivered/uncertain are rejected. From sending, allow delivered or uncertain, or no-send only with the pinned transport's tested typed before-click proof. A delivered receipt must satisfy every identity, full-body/event echo, natural exit and cleanup condition above. From terminal, accept only an identical finish; reject all conflicting transitions and receipts without clearing a hold. Never trust a worker's outcome label alone. Negative tests cover every forbidden phase/outcome pair and malformed receipt.

The broker's held-account status operation performs expired-claimed recovery in its transaction; each held wake calls it before readback and returns even if it clears the last hold. The next future scheduled event may claim. Set `deadline_epoch = due_epoch + 900` as the latest begin_send time, reserving 180 seconds for send and 120 for settlement/cleanup within the 1,200-second due-based ceiling. The worker's effective end is the earlier of that authority ceiling and its monotonic ceiling; a late accepted start never extends authority deadlines.

**Exact reconciliation API:** `reconcile(event, expected_message_digest, proof)` accepts only an existing held event whose sending digest and configured sender/room match. The authenticated trusted worker obtains proof through a single bounded read-only canonical-chat query, not an LLM or substring search over a transcript tail. Proof contains event marker, full normalized body digest, stable message ID, observed sender/room identity and observation time. The normalization is exactly the send normalization, not fuzzy matching. Broker validates fields against the persisted event and trusted account mapping; this is trusted-worker attestation, not protection against a malicious host.

In one transaction: insert immutable positive_readback resolution; keep original uncertain receipt unchanged; remove `holds` only where both account and event match. Effective status is `delivered_reconciled`, derived from the added proof. Duplicate identical reconciliation returns that status; conflicting proof fails. Concurrent hosts reconcile once; crash/retry cannot partially clear the hold or overwrite history. Reconciliation NEVER invokes a send. If a held claim lacks a recorded digest, lookup cannot settle it automatically. A held wake returns after reconciliation or safe claimed-event recovery, even on success; only the next future slot can generate/send.

At each held account's due wake, make at most one read-only lookup. An absent, partial, unauthenticated or unavailable query keeps the hold with its reason; unrelated accounts continue. Do not promise complete history retrieval or automatic recovery for an unobservable event. Historical source ledgers remain immutable. Enrollment enumerates the configured legacy consolidated/per-account JSON states and the finite pilot sender states plus consumed exception receipts; exact existing paths and schema hashes are recorded privately at Task 1, never guessed from a broad home scan. Imports preserve source path/hash/record key; the synthetic event receipt stores raw-record digest and original reason. Every unresolved record imports its own deterministic historical event and `(account,event)` hold in one transaction; multiple records do not reject enrollment or disappear. Collapse records only when exact stored event identity proves they are the same event; otherwise retain distinct holds. Reconciliation or explicit operator release clears one exact hold; any remaining hold blocks new claims. Missing/corrupt required sources reject enrollment for that account with a retained diagnostic until the original source is recovered through its owner, never assumed empty. Other accounts can enroll independently. No fresh empty ledger, consumed one-message exception, or new schedule version bypasses those holds.

### Local event journal and receipt outbox
Each host uses its configured private state directory, mode 0700. `client-events/<sha256-event-key>.json` is mode 0600, max 64 KiB, containing exact event/account, client-generated token, local stage (`claim_ready`, `operation_started`, `sending`, `receipt_ready`, `acked`), timestamps and optional immutable receipt plus digest. Writes use same-directory exclusive temp files, file fsync, atomic replace and parent-directory fsync. A host/account flock spans the invocation and journal recovery, preventing local concurrent replay. Do not put raw provider output or credentials in these records.

On a wake, recover unresolved journal records for that account first. An identical claim_ready request may be retried with its original token; it cannot start work outside its original deadline. Persist operation_started before AGY; a recovered operation_started event is never re-executed, and eventually follows the broker's safe claimed-deadline recovery. Persist sending before the begin_send RPC; dispatch only after its positive reply in this same uninterrupted invocation. A restarted sending record never dispatches, even if the broker returns the same token; it queries status and follows exact reconciliation. A crash before begin_send reaches the broker may be conservative locally, but broker-side claimed recovery is still safe.

Persist a finished transport receipt locally as receipt_ready BEFORE calling finish. On restart/lost reply, replay only this identical finish, never the sender. If authority already stores identical receipt, acknowledge it; if it stores a different terminal receipt, keep the conflict/hold and use the defined reconciliation or operator path. After authority acknowledgment, mark acked. Retain unresolved records indefinitely and only prune acked records older than seven days; the authority's immutable event rows still suppress replay. Journal serialization/locking/recovery/pruning count in the 70-line allocation. Test crashes before and after local replace, begin_send and finish; interrupted writes must expose either the old or new valid record.

### Explicit operator recovery
For an unobservable historical/sending event, a local-only authority CLI `release` may append an `operator_release` resolution containing the exact event, operator attestation/reason, timestamp and proof-reference digest, preserving original receipt and clearing only its matching hold atomically. This operation requires a fresh explicit human direction for that event, verified by the invoking agent, and verified cessation of all associated send workers; possession of an account config or a timer tick is not approval. It is not exposed by the Mac RPC or automatic worker. Existing unrestricted SSH means this boundary is procedural for trusted hosts unless a forced-command SSH identity is configured; it is not claimed as hostile-host isolation. It acknowledges uncertain prior delivery rather than claiming delivered. Duplicate identical release is idempotent; conflicts fail. It sends nothing and only permits a future scheduled event. No hand edit, historical retry or automatic release is allowed.

## STOP, deployment and status
Local STOP is checked before AGY and immediately before transport; authority STOP rejects claim/begin_send. A stop racing an already launched send cannot retract it: receipt still must settle or hold. No promise of instantaneous cancellation after dispatch. Status reports scheduler enablement, installed fingerprint, last outcome, next slot and hold reason separately; delivery never proves task completion.

Before later activation, inventory both hosts' existing services and processes, obtain a coordinated owner handoff, stop only the resolved old sender, verify it is gone, snapshot its recovery records, enroll the new ledger, then enable one replacement service per host. Preserve backups. Restoring an old sender while the new one is active is prohibited. This plan does not execute that replacement.

## Deletion and feasibility acceptance
Remove collection/registry, proposal validation, authority reconstruction, budgets, Beads journaling, publication, model admission, source-candidate binding and dialogue stages from the runtime dependency graph. Retire old CLI modes after caller search. Preserve safety tests or migrate them; delete only tests whose product scope is explicitly removed. No import of coordinator-portfolio.py or old sender/grant machinery.

Before full implementation, prove with focused deterministic tests that the canonical transport can support exact identity/delivery/readback and preserve drafts within the entire 1,000-line budget. Process-supervision simplification requires the stated nested-child/drain tests and independent review. If required transport capability cannot fit, report the measured conflict; do not hide it behind a dependency or approve deployment.

Final acceptance: <=1,000 runtime lines; independent concurrency/crash/uncertainty tests; original ledgers unchanged; no discarded runtime imports; finite processes; separate per-account holds. After code review and explicit activation authority, one real AGY generation check and fresh natural scheduled deliveries for all six host/account pairs, plus the next scheduled cycle, must have exact receipts/readback. Existing authentication gaps and ambiguous historical sends may block specific accounts; report them, do not manufacture success. No arbitrary 12-hour pilot is required to prove two cycles.

## Self-review
The design keeps one generator, one sender, one authority and one small schema. It names the known missing browser capability and makes feasibility an executable prerequisite rather than declaring it implemented. The line cap includes recovery and transport work. The explicit reconcile transaction closes the previous review finding without changing original receipts or resending held events.
