# Skill archive — 2026-11-09 (no usage evidence)

## Specification

- **Outcome:** skills archived on the operator's Mac for lack of usage evidence stay archived after a later install or sync from this repository.
- **Non-goals:** no install, sync or live-home change; no command file deleted (unused ones are moved to `.claude/commands_archive/`); no rule or workflow change in any active skill; no change to `hermes/skills/`, `portable/skills/` or `shared/aliases/`.
- **Acceptance:** every archived name that this repository ships as an installable skill is either under `.claude/skills_archive/2026-11-09-no-usage-evidence/` or listed below as held with the reference that blocks it; every command file whose skill-form copy was archived is either under `.claude/commands_archive/2026-11-10-no-usage-evidence/` or listed below as held with its reference; `scripts/install_shared_catalog.py` and `install-claude-commands.sh` no longer select the moved names; the inventory, portability and archive contract tests give the same results as on the base revision.
- **User story:** the operator trims unused skills on a host, later runs the installer, and the trimmed skills do not come back.
- **Proof:** the repository contract tests on this branch and on the base revision; reference scan of the moved names across active skills, commands, hooks, launchd templates, scripts, workflows and instruction files; an install of the base revision into an empty scratch home followed by `install-claude-commands.sh --merge --migrate-archives --all` from this branch.
- **Mock:** not applicable; no visual interface.
- **Risk:** a host that still uses one of the moved skills or commands loses it at the next install or sync; each can be restored with `git mv` as the two archive `README.md` files describe. The installer's archive migration refuses a skill name held by two archive groups, so a moved name must not already exist in an older group; `xlsx` did, and its older copy is removed here (see References touched).
- **Limits:** 284 of the 308 names were never shipped as skills by this repository, so nothing here can stop whatever created them from creating them again (see Generator finding).

## Evidence used for the trim

A skill was archived when none of these held: an explicit skill call, a file open or a typed `/name` in Claude Code history; a skill-file open by a Codex tool call on either host in the last 14 days; a mention in an always-loaded instruction file; creation in November 2026. Operator-named keeps (`diskm`, `innovate`, `secondo`, `plan`, `converge`, `fullrun`, `fixprc`) were excluded from the trim. `legacy-command-compatibility` was explicitly rejected by the operator.

## Generator finding

No script in this repository, at `origin/main` or anywhere in its history, produces the `claude-command-*`, `extended-library-*` or short alias wrappers. Each wrapper is a two-file package: a `SKILL.md` that says to read a canonical skill or command under the Claude home, and `agents/openai.yaml` with `policy.allow_implicit_invocation: false`. `shared/comparison-decisions.json` already records them as `preserve-unmanaged-generated-wrapper` ("Generated legacy command wrapper; do not duplicate into shared canonical catalog"). They were created on the host outside this repository, so there is no generator input or exclusion list to change here. `legacy-command-compatibility` is likewise a host-local package (`preserve-unmanaged-local-package`); it has never been in `.claude/skills/`, so there is nothing to remove from the active set.

`scripts/install_shared_catalog.py` installs every directory with a `SKILL.md` under `.claude/skills/`, `portable/skills/` and `shared/aliases/`, minus `shared/retain-local.json`. Moving a directory out of `.claude/skills/` is therefore sufficient to stop it being installed; given the previous receipt as `--baseline-receipt`, the installer also retires the unchanged live copy.
