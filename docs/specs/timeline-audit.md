# Timeline audit specification

- **Outcome:** A retrospective HTML timeline and written audit of every 20-minute slot in the requested window; default four hours.
- **Non-goals:** No new runner, automatic publication, utilization inference, or resumption of audited work.
- **Acceptance:** Honor explicit boundaries; cover every contiguous slot including the final partial slot; cite admitted evidence; label unobserved time unknown; retain failures and source limits.
- **User story:** An operator investigating a long run can distinguish evidenced progress, repeated work and unknown intervals.
- **Proof plan:** Validate skill metadata and command argument forwarding, check installed package counts, and inspect one real retrospective report for complete slot coverage and rendered output.
- **Mock exemption:** No application UI changes; reuse the existing retrospective timeline renderer.
- **Risk:** Sparse history can suggest false inactivity or causality. Preserve uncertainty, exclude hidden reasoning and secrets, and keep history-derived artifacts local unless publication is requested.
