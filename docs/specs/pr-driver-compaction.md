# PR driver compaction specification

## Outcome
Reduce always-loaded driver explanation while preserving the full fix-all-before-push contract.

## Non-goals
Do not change review, evidence, CI, merge, security or publication authority; do not revive archived babysit automation or modify executable code.

## Acceptance
The five-step enumerate/classify/fix-all/verify/push loop, root-cause grouping, selective staging, verification-before-push, retry handling and explicit anti-patterns remain. The worked example still covers shared and independent failure causes. Archived observer pairing remains inactive. Canonical lifecycle policy stays authoritative.

## User stories
No user-facing application change. An engineering agent can read a shorter explanation and still discover all required driver steps and restrictions.

## Proof plan
Compare full before/after skill content and semantic inventory. Preserve original source, test and review pins. Use focused mechanical/installer tests and current-head hosted CI. Independent source and applicable CS/Ponytail/evidence receipts must be published with actual coverage. Retain the original WITHHELD disposition until its missing-spec/publication gaps are resolved; no automatic approval from adding this file.

## Mock exemption
No rendered interface, interaction, displayed-data, browser, native or provider behavior changes. Visual mocks/media do not apply.

## Risk
Compaction could omit constraints or imply archived orchestration is live. Full-scope independent reading checks that risk. Original historical test provenance remains limited to retained records; new hosted CI is identified separately. This specification adds no operating rule or merge permission.
