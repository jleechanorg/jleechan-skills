# Mark PR nudger target expired on deadline wrapper exit 124

- **Outcome:** Treat exit code `124` from the enrolled deadline wrapper across route, resume, bootstrap, and pending-delivery reconciliation paths in `scripts/pr_nudger_routes.py` and `scripts/pr_owner_nudger.py` as terminal `"expired"`, stopping further nudger scheduling and wakes until the target is re-enrolled.
- **Non-goals:** No changes to `scripts/pr_nudger_round.py` wrapper generation, no automatic re-enrollment or deadline extension, and no changes to non-deadline exit codes (`0`, `1`, etc.) or `reconciliation_required` handling when no exit `124` occurred.
- **Acceptance:**
  1. `_supported_codex`, `_resume`, `_wait_for_receipt`, `start_codex_bootstrap`, `inspect_codex_bootstrap`, `inspect_agy_bootstrap`, and `verify_delivery_expired` in `scripts/pr_nudger_routes.py` return `"expired"` (or `("expired", None)` / `True`) on wrapper exit code `124` without an accepted transcript delivery, while preserving `"delivered"` if delivery was accepted before exit `124`.
  2. `dispatch()`, `reconcile_delivery()`, `dispatch_target()`, and `tick()` in `scripts/pr_owner_nudger.py` transition the target to `status="expired"`, `next_action="expired"`, clear any pending `bootstrap` / `pending_delivery` state, and stop waking it on subsequent ticks, transient GitHub refresh errors, CI completions, stage changes, or head advances.
  3. Re-enrolling an expired bootstrap-managed target (whether it expired after binding or during bootstrap) with changed `cli`, `cli_bin`, `profile_dir`, or `model` clears the expired state and returns `"enrollment_changed"` so the next tick bootstraps the new enrollment.
- **User story:** When an enrolled PR owner's deadline expires (exit `124`), the nudger stops polling and waking that target instead of getting stuck in `reconciliation_required` or `blocked_cli_auth` loops, and resumes cleanly only if the operator re-enrolls the target.
- **Proof plan:** Reproduce the pre-change `reconciliation_required` / `blocked_headless_exclusion_unverified` / `bootstrap_pending` failures on the exact pre-change base revision (`aa752dfa6bf2f99f061d9bc41e773ca7b6a0fb2a`) using real deadline wrappers (`timeout` / exit `124`) across route, bootstrap, and SQLite tick boundaries; run the identical scenario at the candidate head; pass `tests/test_pr_nudger*.py` and repository contract tests; and pass `/cs`, `/advice` (2 independent source votes), and `/er`.
- **Mock exemption:** Unit and contract tests isolate GitHub REST/GraphQL calls, host capacity probes, and `cmux` with disposable SQLite/git-worktree fixtures and real subprocess deadline wrappers (`bash` / Python executable scripts returning `124`).
- **Risk:** Treating exit `124` as `"expired"` even after a transcript row was already written would misclassify a completed delivery; `_wait_for_receipt` and `reconcile_delivery` check transcript delivery first so `"delivered"` wins whenever the prompt was accepted.
