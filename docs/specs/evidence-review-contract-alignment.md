# Evidence and reviewer contract alignment

## Outcome
Activate one coherent reviewer contract across the shared catalog and both live
hosts. Preserve complete source proof and evidence-only proportionality while
using the merged reviewer tiers and risk-selected count.

## Non-goals
No new runner, parser, timer, account, credential, provider retry or application
request. No merge-authority change, blanket documentation exemption or source
approval from an evidence-only verdict. Do not silently adopt PR696's unmerged
record-only exception or overwrite substantive live-only rules.

## Acceptance
- Preserve current main's risk table, tiers/class caps and separate mandatory
  gates; one-source-review routes require positive lifecycle eligibility.
- Advice is the sole access-mode/field/check table; static-review owns the exact
  prompts and compatible clone/export/read-only/remote/packet/saved preambles.
- Every code approver has the complete diff and every changed object at both
  pins or verified absence; truncation/partial coverage cannot approve.
- Evidence-only review derives the complete changed-claim map and inspects the
  actual claim-relevant artifacts without inheriting full-code vote scope.
- Hidden outside model/private account fields are never fabricated; positive
  private session identity and source-author independence are still required.
- No new copy solely for independence when complete read-only access exists.
  Actual copy/process/clock checks apply only to the selected access mode.
- Preserve original review SHAs/times/statuses. Capture private receipts and
  cleanup inside the attempt budget; later redacted publication is separate.
- Source and live Mac/Linux copies are compared before scoped apply. Preserve
  Mac full-object coverage and Linux access modes; preserve the Mac Hermes
  alias and resolve independent Linux Hermes ownership before overwriting.

## User story
Before, callers can load mismatched advice/static modes, over-scope evidence
review, or reject a Dot because its hidden runtime name is unavailable.
After, the same canonical contract selects available complete-access reviewers,
uses one reviewer only for qualified low-risk source review, and retains
stricter source/evidence/merge requirements.

## Proof plan
Run focused frontmatter/link, command-closure, installer/portability and lifecycle
checks; no prose-pinning tests. Review before/after scenarios for missing tools,
complete API access, exports, hidden outside metadata, same-account aliases,
partial or wrong-head output and evidence-only scope. Run autonomy/source-cite
canaries before/after where the shared runtime-adapter gate applies. Batch the
source before independent reviews; retain usable earlier proof with explicit
delta applicability instead of rerunning it for phase labels.
