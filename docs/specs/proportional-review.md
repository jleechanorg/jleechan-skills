# Proportional PR review

## Outcome
Use one lifecycle-owned table to select proof and independent source coverage from changed claims and risk. Keep the workflow manager as the discovery, ownership and publication preflight.

## Non-goals
No new runner, scripts, tests, CI, install action or persistent runtime configuration. No change to merge authority, separate domain safeguards or repository overrides. This instruction-policy change retains its own independent review.

## Acceptance
- Classify editorial, package integrity, agent policy, small deterministic code, UI presentation, UI interaction, ordinary/cross-module, service-boundary and high-risk changes explicitly.
- Apply repository requirements and highest-risk effects before numeric admission; small deterministic admission is at most 150 production delta lines and three runtime files in one module plus tests, with all exclusions satisfied.
- Positively qualified low-risk work uses one cold full-coverage static reviewer directly, without size-triggered advice, Dot or provider-ladder ceremony.
- Ordinary, changed-boundary and high-risk work retains the stronger two-source-vote route; policy changes retain applicable review and cannot self-exempt.
- Proof follows changed claims: existing service use and deployment alone do not create a new boundary or gameplay claim. Actual boundary changes require real integration proof.
- Reuse valid proof/coverage across phases with original SHA attribution; a source vote does not depend on the existence of a later readiness approval.
- Preserve applicable separate evidence seats, publication/readback, current checks and independent merge authority.

## User story
An author changing an icon or a deterministic helper gets focused proof and complete review; an author changing permissions or persistence still receives independent risk scrutiny. Reviewers can identify the route and its exclusions without reconstructing several threshold sections.

## Proof plan
Run existing structural/portability and installer checks relevant to exported Markdown, diff whitespace validation, and before/after semantic canaries. Independently review complete changed policy and the route for exclusions, quorum, evidence, repository precedence and merge separation. No application runtime behavior is claimed.

## Evidence boundary
Icon/splash appearance requires rendered proof; copy, attribution and links require the claimed literal/provenance/destination checks. An existing Apple-logo asset does not imply a new gameplay claim. Actual signing, release, legal, trust or interaction effects retain their own proof and risk classification.

## Risks and ownership
Misclassification can hide a required gate. The lifecycle's explicit criteria, highest-risk precedence and independent eligibility finding address that risk. Static-review owns cold reviewer inputs/identity, evidence owners retain adjudication/publication, and merge owners retain exact-head quorum/authority. Repository overrides remain controlling.
