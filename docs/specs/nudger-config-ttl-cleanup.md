# Auto-prune closed and expired targets from PR nudger config

- **Outcome:** Automatically prune closed/merged targets (configurable `prune_closed_after_hours`, default `0`) and expired targets (configurable `prune_after_hours`, default `24`) from the nudger `config.json` and `receipts.sqlite3` during `pr_owner_nudger.py --apply` ticks and via `scripts/pr_nudger_round.py prune`, using atomic `0600` config writes (`save_config`) that preserve concurrent edits made mid-tick.
- **Non-goals:** No pruning of active open targets, open `final_ready` targets, or open `observe_only` non-expired targets; no deletion of git worktrees or profile directories on disk; no changes to `tick` behavior without `--apply`.
- **Acceptance:**
  1. `scripts/pr_nudger_intake.py` (`Intake.prepare` schema migration + `Intake.schedule`) records and preserves `expired_at` and `closed_at` timestamps in `target`, clearing them on non-expired/non-closed transitions.
  2. `scripts/pr_owner_nudger.py` (`tick` with `--apply` / `config_path`) validates `prune_after_hours` and `prune_closed_after_hours` (failing closed on non-numeric, negative, boolean, or non-finite values), prunes `closed` targets after `prune_closed_after_hours` (default `0`) and `expired` targets after `prune_after_hours` (default `24`) via `prune_config_targets` (re-reading disk config, matching pre-tick snapshots to preserve concurrent edits, writing atomically with `0600` via `save_config`, and cleaning up SQLite `target`/`target_ci`/`delivery`/`binding` rows via `delete_target_state`), and never prunes when `--apply` is omitted.
  3. `scripts/pr_nudger_round.py prune` supports `--dry-run`, `--prune-after-hours`, and `--prune-closed-after-hours`, reuses `prune_config_targets` and `save_config` for atomic `0600` updates (also routing `save()` through `save_config`), and handles closed PRs, SQLite `expired_at` / `delivery`, and expired `-deadline-<epoch>` enrollment wrappers while keeping active and `observe_only` non-expired targets.
- **User story:** Operators running multi-round PR nudgers no longer accumulate stale closed, merged, or expired entries in `~/.config/pr-owner-nudger/config.json`; closed targets are cleaned up immediately (or after a configured grace period) and expired targets are retained for a 24-hour inspection window before automatic removal, with manual `pr_nudger_round.py prune --dry-run` / `prune` available on demand.
- **Proof plan:** Reproduce the pre-change behavior on exact base `3277d71113477d6b12dd491fa40441ad33681aaa` where closed/merged and expired targets remain indefinitely in `config.json` and `pr_nudger_round.py prune` is missing; run the identical real-SQLite/real-file scenario at the candidate HEAD; pass `tests/test_pr_owner_nudger.py`, `tests/test_pr_nudger_round.py`, sibling nudger suites, portability scans, and repo contract tests; and pass `/cs` + `/ponytail`, `/advice` (2 independent votes), and `/er`.
- **Mock exemption:** GitHub REST/GraphQL endpoints and subprocess wrappers are isolated in tests and real-boundary repro scripts using disposable `config.json` (`0600`) files, real SQLite `receipts.sqlite3` databases, and real `pr_owner_nudger.main` / `pr_nudger_round.main` CLI invocations.
- **Risk:** Rewriting `config.json` mid-round could clobber concurrent `enroll` or `retire` edits made during GitHub API calls, or relax `0600` permissions. `prune_config_targets` mitigates both by re-reading `config.json` immediately before replacement, only removing items still byte/dict-equal to the tick's pre-check snapshot, and writing atomically via `tempfile.mkstemp` + `os.fchmod(0o600)` + `os.fsync` + `os.replace`.
