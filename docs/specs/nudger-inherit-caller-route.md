# Inherit the nudger's CLI and model from the calling agent

- **Outcome:** `/pr --nudge` resolves its enrolled PR owner's route from the calling agent instead of requiring the operator to name it. `scripts/pr_nudger_round.py` gains `resolve_route()`, which returns the `(cli, model)` pair together: giving both `--cli` and `--model` uses them as-is; an explicit `--model` without `--cli` derives the CLI from that model's family (and refuses unsupported Claude-family models); an explicit `--cli` keeps the caller's model only when it fits; neither flag lets the caller's own model decide both (with inherited Claude-family models falling back to `agy` + `gemini-4-hydrogen-high`); and with no caller model at all the route falls back to `agy` + `gemini-4-hydrogen-high`. Seven previously unregistered environment variables become the inheritance source and are added to `docs/portability-env-vars.md` in this same change.
- **Non-goals:** No change to `--hours`, `--scope-file`, `--policy`, `--profiles-dir`, `--cli-bin`, `--headless-only`, `retire` or `retry-now`; no change to the deadline wrapper, the bootstrap protocol, the tick scheduler, or the dispatch/merge boundary. Not an attempt to make the nudger choose reviewers, evidence, or merge authorization.
- **Acceptance:**
  1. `cli_for_model()` classifies `gemini-*` as `agy`, Claude identifiers (`claude*`, `opus*`, `sonnet*`, `haiku*`) as a family **no** enrolled CLI can run, and everything else as `codex`.
  2. `family_matches("claude-opus-5-5", "codex")` is `False`, so a Claude model can never be enrolled for a `codex` owner.
  3. A caller model no enrolled CLI can run (`CLAUDE_MODEL=claude-opus-5-5` with no other variable set) falls back to `agy` + `gemini-4-hydrogen-high` rather than enrolling a route that fails at bootstrap.
  4. Passing both `--cli` and `--model` uses them as-is; passing `--model` without `--cli` derives `agy` for `gemini-*`, derives `codex` for non-Claude models, and refuses Claude-family models (e.g. `--model claude-opus-5-5`) with a named error instead of enrolling on `agy`.
  5. All seven variable names appear in `docs/portability-env-vars.md`.
  6. `docs/pr-owner-nudger.md` and `.claude/skills/pr-owner-nudger/SKILL.md` describe the inheritance order, fallback, and refusal rules.
- **User story:** An operator running `/pr --nudge <PR>` from a Claude, Gemini, Codex or Pi session gets a PR owner on that same model and CLI without repeating either value, and cannot accidentally enrol an owner whose CLI would reject the inherited model.
- **Proof plan:** `tests/test_pr_nudger_round.py` exercises the route matrix through the real CLI against a disposable git fixture: inheritance from each env family, family mismatch, explicit-flag precedence, as-is behavior when both flags are given, refusal of an unsupported `--model` without `--cli`, and the no-caller fallback. Re-run the sibling nudger suites (`test_pr_owner_nudger.py`, `test_pr_nudger_github.py`) and the repository contract suite; compare failures against baseline `origin/main`. Capture the actual `enroll` output and persisted enrollment JSON for each row, bound to the head SHA, and publish it as the PR's evidence.
- **Mock exemption:** Not applicable — the tests drive the real `enroll` command against a real disposable git repository and assert on the persisted enrollment JSON; only the CLI binary lookup is stubbed, because enrolling a real owner would launch a paid model session.
- **Risk:** Changing the default `--cli` from `codex` to a caller-derived value changes behaviour for anyone relying on the old implicit default; `--cli codex` remains one flag away. Model-family classification is prefix-based, so a future model family that serves `agy` without a `gemini` prefix would be misclassified as codex-compatible and rejected at bootstrap rather than silently accepted.
