## Summary

`/pr --nudge` now defaults `--cli` to `agy` and can inherit the calling agent's own model, so a dispatch no longer has to name the model twice and an `agy` owner is the default rather than opt-in.

## Behaviour not asked for

None. Both changes were requested by the operator: "agy and by default lets have nudger use the calling model, modify jleechan skilsl repo with PR".

## Background

`scripts/pr_nudger_round.py` declared `--cli` with `default="codex"` and `--model` as `required=True` with no inference. Every enrollment therefore had to hardcode a model string, and the calling agent's model — already present in the environment — was ignored.

## What changed

- `--cli` default: `codex` → `agy`.
- `--model` is optional. Omitting it inherits the caller's model from `PR_NUDGER_MODEL`, `PI_MODEL`, `CLAUDEWA_MODEL`, `CLAUDE_MODEL`, `CODEX_MODEL`, `AGY_MODEL`, `GEMINI_MODEL` (first set wins).
- Family guard: an inherited model is taken only when it matches the selected CLI's family (`gemini-*` → `agy`, else `codex`). Handing `agy`'s model to `codex` would enroll an owner whose CLI rejects it.
- With no `--model` and no usable caller model: `agy` falls back to `gemini-3.8-flash-high`; `codex` fails closed with the env list named. An explicit `--model` always wins.

## Tests

`tests/test_pr_nudger_round.py` gains 6 cases: `--cli` defaults to `agy`; `agy` inherits a gemini model; `codex` inherits a non-gemini model; cross-family is refused for `codex`; explicit `--model` wins; fallback applies with no caller model. The pre-existing enrollment test now passes `--cli codex` explicitly, since its `auth.json`/wrapper assertions describe Codex.

Local: `52 passed, 20 subtests passed` across `tests/test_pr_nudger_round.py tests/test_pr_owner_nudger.py tests/test_pr_nudger_github.py`.

## Evidence

End-to-end against the real CLI on a throwaway git fixture (not mocks), each case confirmed from the persisted enrollment JSON:

| Case | Command | Result |
|---|---|---|
| No env, no `--model` | default | `agy` / `gemini-3.8-flash-high` |
| `AGY_MODEL=gemini-9.9-caller` | default | `agy` / `gemini-9.9-caller` |
| `PI_MODEL=deepseek-v4.1-flash` | `--cli codex` | `codex` / `deepseek-v4.1-flash` |
| `AGY_MODEL=gemini-9.9-caller` | `--cli codex` | refused: `enroll needs --model, or a caller that advertises its model ...` |
| `AGY_MODEL=gemini-9.9-caller` | `--model pinned-model` | `agy` / `pinned-model` |

This is CLI/enrolment behaviour, not a user-visible UI change, so there is no video: the applicable non-visual evidence class is the command/JSON table above.

## Risks

- Changing the `--cli` default changes behaviour for anyone relying on the old implicit `codex`. Mitigated by the loud `enroll ... (agy)` line and by `--cli codex` remaining one flag away.
- `CALLER_MODEL_ENV` reads process environment, so a host with a stray `GEMINI_MODEL` would now influence an unqualified `agy` enrollment. That is the requested inheritance; the family guard bounds it.
