# Coordinator source transition

This revision removes coordinator profile-flock acquisition, shared STOP checks, pending-send records and legacy delivery-ledger reads. It does not delete their live files. The shared `dot.sh` transport lost the same controls in this revision, so no Dot caller keeps a STOP reservation or a per-profile flock any more. Concurrent profile access and duplicate later sends after unknown outcomes are accepted risks of removal; Chrome SingletonLock/process checks are not equivalent to a shared flock or destination idempotency.

Before separately approved host activation, the runtime owner must establish quiescence, reconcile uncertain sends and preserve a complete recoverable snapshot of old skill/config/state. Never delete or replace a held lock inode, browser profile, credentials or service files. Do not rewrite schedules or activate both label sets. Install both neutral and compatibility packages together, retain executable forwarding paths, and keep exactly one existing cadence. Existing installed PR538 is unchanged by this source revision.

`dot.sh` no longer holds a per-profile flock or creates a coordinator STOP marker either, so no caller is mutually excluded any more; its disk-floor, foreign-binary, SingletonLock and process-teardown checks remain. Do not claim two concurrent Dot callers on one profile are serialized. Old state is archival evidence after separately approved cutover, not a dispatch prerequisite. Preserve it rather than bulk-delete. Rollback restores old source/config only after quiescence and owner reconciliation; it must not reactivate a second schedule set. No automatic merge, install, service switch or credential change is included.
