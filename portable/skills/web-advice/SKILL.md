# Web advice

This is real vendor web-chat review, distinct from internal [advice](../advice/SKILL.md). An invocation must establish the content, external recipients and sharing scope; do not submit private source merely because it may improve a review. Never export credentials, cookies, session tokens or personal data to make a browser work.

Use only the current runtime's supported browser control and an authorized existing signed-in session. Respect the requested browser/window and visible/headless constraints. Do not decrypt/replay cookies, extract Keychain values, bypass browser/app denials, or assume headless support. If authentication/transport is unavailable, report UNAVAILABLE and continue other authorized work. Do not relabel internal agents, APIs or search synthesis as web-chat review.

Prepare a bounded complete review packet for the authorized scope: exact revision/diff and necessary full changed files for code, actual documents for document review, and evidence only when pertinent. Redact sensitive content before transmission; a bare private PR URL does not give an external reviewer access. Start the prompt with [web advice], ask for a matching conversation title, and send materially equivalent context to each authorized reviewer.

For each seat verify the intended vendor/account context, attachment or prompt delivery, real returned response, exact revision and filenames actually covered. Report APPROVED, APPROVED with notes, CHANGES REQUESTED or REJECTED as returned, with reasoning, risk, confidence, coverage and source links where applicable. Distinguish requested model identity from verified UI/runtime identity.

Synthesize agreements, disagreements and missing coverage without inventing quorum. Preserve authorized local response receipts. Creating share links, public gists or PR posts is a separate sharing action, not an automatic final step. Avoid duplicate submissions when a prior seat already attempted the same packet.
